This file provides guidance to Codex (Codex.ai/code) when working with code in this repository.

## Build Commands

**Desktop (Linux / Windows / macOS):**
```bash
mkdir build
cd build
cmake -DCMAKE_BUILD_TYPE=Release -S .. -B .
cmake --build . --config Release
```

**Test coverage (Catch2 suite):**
```bash
cmake --build build --config Release --target fc-tests
ctest --test-dir build -C Release --output-on-failure
```

**Line coverage report (Windows / MSVC):**
```powershell
# Install once if needed:
winget install OpenCppCoverage.OpenCppCoverage

cmake --build build --config Debug --target fc-tests
$repo = (Get-Location).Path
OpenCppCoverage `
  --sources "$repo\ficsit-companion\src" `
  --sources "$repo\ficsit-companion\include" `
  --excluded_sources "$repo\build" `
  --excluded_sources "$repo\build-codex" `
  --export_type cobertura:coverage.xml `
  --export_type html:coverage-html `
  -- "$repo\build\ficsit-companion\Debug\fc-tests.exe"
```
Open `coverage-html/index.html` for an HTML report, or load `coverage.xml` in VS Code with a coverage extension such as Coverage Gutters.

Cmder / `cmd.exe` equivalent:
```bat
winget install OpenCppCoverage.OpenCppCoverage

cmake --build build --config Debug --target fc-tests
OpenCppCoverage --sources "%CD%\ficsit-companion\src" --sources "%CD%\ficsit-companion\include" --excluded_sources "%CD%\build" --excluded_sources "%CD%\build-codex" --export_type cobertura:coverage.xml --export_type html:coverage-html -- "%CD%\build\ficsit-companion\Debug\fc-tests.exe"
```

**Web (Emscripten/WASM):**
```bash
# Requires emsdk installed and activated: source emsdk/emsdk_env.sh
mkdir build
cd build
emcmake cmake -DCMAKE_BUILD_TYPE=Release -S .. -B .
cmake --build . --config Release
```

Dependencies (SDL2, ImGui, ImGui Node Editor, nlohmann/json) are fetched automatically via CMake `FetchContent` — no manual install needed.

There are no linters configured.

## Architecture Overview

**ficsit-companion** is a cross-platform, node-based production planner for the game Satisfactory. It targets desktop (SDL2 + OpenGL) and web (Emscripten/WASM). The UI is built entirely with Dear ImGui + ImGui Node Editor.

### Class Hierarchy

```
BaseApp (abstract, in base_app.hpp)
  └─ ProductionApp          ← main application logic (production_app.hpp/cpp)
```

`ProductionApp` owns the full node graph and drives the main loop: load game data → deserialize saved session → render UI → propagate rates → serialize on change.

### Node System (`node.hpp`, `node.cpp`)

Polymorphic node hierarchy:
- `Node` — base (id, label, input/output pins, position)
- `PoweredNode : Node` — adds machine rate / overclock / power calculations
  - `CraftNode` — a production machine running a `Recipe`
  - `GroupNode` — collapses a sub-graph into a single node
  - `CustomSplitterNode` / `GameSplitterNode` / `MergerNode`
  - `SinkNode` — AWESOME Sink terminal

### Graph Connections (`pin.hpp`, `link.hpp`)

- `Pin` — typed connection point (input or output) on a node; holds a `FractionalNumber` rate and a lock flag
- `Link` — directed edge between one output pin and one input pin; at most one link per pin

### Rate Propagation

`UpdateNodesRate()` in `ProductionApp` propagates item rates through the graph (BFS over `Link` connections). All rates are stored as `FractionalNumber` (exact rational arithmetic, `fractional_number.hpp/cpp`) to avoid floating-point drift.

### Game Data (`game_data.hpp/cpp`, `recipe.hpp`, `building.hpp`)

`GameData::LoadData()` parses `assets/satisfactory.json` (generated by `scripts/data_extractor.py` from the game's `Docs.json`) into:
- `Item` — display name, sink value, icon path
- `Recipe` — inputs/outputs with quantities, producing building, base power
- `Building` — machine power specs, overclock support, tier/category

### Persistence

- Session: `saved/last_session.fcs` — JSON graph snapshot, loaded/saved via `json.hpp/cpp`
- Settings: `settings.json` — spoiler visibility, unlocked alt recipes, power display mode

### Key Files

| File | Role |
|------|------|
| `ficsit-companion/src/production_app.cpp` | Core app (~4 000+ lines): all UI rendering, node graph logic, serialization |
| `ficsit-companion/include/production_app.hpp` | `ProductionApp` class declaration |
| `ficsit-companion/include/node.hpp` | Full node hierarchy |
| `ficsit-companion/include/fractional_number.hpp` | Exact rational arithmetic |
| `assets/satisfactory.json` | Game data (do not edit by hand; regenerate via `scripts/data_extractor.py`) |
| `cmake/imgui.cmake` | Fetches and configures ImGui + ImGui Node Editor |

### Web vs Desktop Differences

`main.cpp` uses `#ifdef __EMSCRIPTEN__` guards to switch between the SDL/OpenGL desktop loop and the Emscripten `emscripten_set_main_loop` callback. File I/O on web uses the Emscripten virtual filesystem; settings and saves are persisted via `EM_ASM` localStorage calls.
