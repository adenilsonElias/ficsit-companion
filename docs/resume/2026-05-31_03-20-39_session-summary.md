## Open issue at end of session

The user reports that the *last storage in a chain coming off a smart
splitter's overflow output* still shows **Circuit Board** on its output
pin, even after the fixes below. The latest patches removed the bad
back-propagation paths and added a forward-propagation pass, but the
symptom persists. Likely remaining cause to investigate next session:

- A path other than the at-wire mirror is still painting the item onto
  the storage chain. Suspect: `CreateLink` / item-propagation that runs
  when the session is loaded from `last_session.fcs` rather than freshly
  imported (the user may be looking at a cached graph).
- Or: an unguarded item-copy in the rate-propagation `link` loop where
  the downstream item gets overwritten when the upstream pin is a CraftNode
  with a different item.
- Repro recipe: import the user's save, find a smart-splitter overflow
  branch terminating in a CraftNode whose input is Circuit Board, walk
  back through the storage chain, and instrument `sav_import.cpp` to log
  each pin's item assignment.

## Changes applied in this session

Each entry lists files touched and intent.

### 1. Conveyor lift / ceiling attachment detection
- `tools/sav_import/wrapper.js:246-249`
- Extended `belt_pole` detection to cover `Build_ConveyorLift*` and
  `Build_ConveyorCeiling*`. Belt-chain walks no longer dead-end at lifts,
  which previously caused dozens of dropped belts on imports.

### 2. Save-port rank-based pin mapping
- `src/sav_import.cpp` (BuildGraph)
- Save naming is inconsistent: splitters/mergers use 1-based bare
  `Input1`/`Output1`, manufacturers use descriptive names like
  `InputInventory0` (0-based), and some buildings expose the conveyor
  at a non-zero save-port.
- Replaced direct save-port-as-pin-index with **distinct save-port sets
  ranked ascending → dense C++ pin indices**. Splitter/merger get
  identity; manufacturers and storage collapse onto pin 0..N-1.

### 3. Item-aware routing for multi-port CraftNodes
- `src/sav_import.cpp`
- For CraftNodes with >1 input or >1 output, look up the belt's resolved
  item and pick the pin whose `item ==` matches, instead of trusting the
  rank order. Fixes Reinforced Iron Plate assembler where save physical
  port order may not match recipe declaration order (Iron Plate ↔ Screw
  swap).

### 4. Per-belt item resolution with iterative propagation
- `src/sav_import.cpp`
- **Seed phase**: belts touching a single-output Extractor, a
  single-output CraftNode, or a single-input CraftNode pick up that
  endpoint's item.
- **Iterative propagation**: belts touching organizers/logistics inherit
  from siblings until fixed point.
- Smart/programmable splitters are excluded from propagation (see #11).

### 5. Organizer item ChangeItem pass
- `src/sav_import.cpp`
- After wiring, for each belt with resolved item, call
  `OrganizerNode::ChangeItem` on connected organizer endpoints so the
  editor renders pin icons and future rate edits don't fail item checks.
- `CustomSplitterNode` excluded.

### 6. Forward rate propagation
- `src/sav_import.cpp` (post-wiring loop, ≤64 iterations)
- Rules:
  - Merger output = `sum(inputs)`
  - GameSplitter/CustomSplitter outs = `input / count(connected outs)`
  - Logistics outs = `sum(inputs) / count(connected outs)`
  - Link copy: downstream input rate = upstream output rate, except for
    CraftNode/Extractor pins (recipe-bound).

### 7. Dimensional Depot
- `include/node.hpp` — `LogisticsNode::Kind::DimensionalDepot = 4`
  (appended; preserves save compat).
- `src/node.cpp` — `GetDisplayName` returns `"Dimensional Depot"`;
  `LogisticsNode` ctor allows 0 outputs *only* for this kind.
- `include/sav_import.hpp` / `src/sav_import.cpp` — `BuildingKind::DimensionalDepot`,
  parsed and built with 1 input + 0 outputs.
- `src/production_app.cpp` — add-node menu entry and dispatch.
- `tools/sav_import/wrapper.js` — `Build_DimensionalDepot*` and
  `Build_StorageDimensional*` → `"dimensional_depot"`.

### 8. Truck/Train Station fuel pin
- Stations now always have **3 inputs** (cargo 0/1 + fuel 2) and 2 outputs.
- `tools/sav_import/wrapper.js:609-637` — `getComponentPort` emits
  `role: "fuel"` when the suffix matches `^Fuel | ^InputFuel | ^OutputFuel`
  (tightened from a permissive `/Fuel/` regex after a false positive).
- `tools/sav_import/wrapper.js:756-757` — belt entries carry `src.role`
  and `dst.role`.
- `include/sav_import.hpp` — `Belt::src_role` / `Belt::dst_role`.
- `src/sav_import.cpp` — parses the role; partitions observed save-ports
  into cargo (rank-mapped) vs fuel (routed to last pin); always
  allocates the fuel pin on stations; fuel routing also validated
  via `IsFuelItem` so a non-fuel belt the wrapper mis-flagged falls
  back to cargo rank.
- `src/production_app.cpp` — menu now creates stations with 3 in / 2 out.

### 9. Fuel-only pin enforcement in `DragLink`
- `src/production_app.cpp`
- `IsFuelPin(pin)`: true for the last input on Truck/Train station.
- DragLink rejects (red flash) when one end is a fuel pin and the other
  has a non-null item that isn't a known fuel.
- `IsFuelItem` lives in `utils.cpp` / `utils.hpp` for sharing between
  `production_app.cpp` and `sav_import.cpp`.
- Recognized fuels (extend if mods add more):
  Solid Biofuel, Coal, Compacted Coal, Petroleum Coke, Packaged Liquid
  Biofuel, Packaged Fuel, Packaged Turbofuel, Packaged Rocket Fuel,
  Packaged Ionized Fuel, Battery.

### 10. Miner menu refactor (smelter-style)
- `src/production_app.cpp`
- Removed `Miner Mk1 / Mk2 / Mk3` top-level entries.
- Added `Miner ▶` submenu listing each mineable resource (Iron Ore,
  Copper Ore, Caterium Ore, Limestone, Coal, Sulfur, Bauxite, Raw Quartz,
  Uranium, S.A.M.). Picking one creates a Mk1 miner with that resource
  preset; user changes Mk/purity via the existing in-node buttons.
- Removed the auto-overwrite on extractor resource: `CreateLink` and
  `PropagateExtractorResourceUpstream` now only assign when
  `ex->resource == nullptr`. Picking a resource explicitly is sticky.

### 11. Smart/Programmable splitter item-opacity
- `src/sav_import.cpp`
- `ResolveDownstreamItem` BFS stops at `IsCustomSplitter()` — fixes the
  bug where a coal miner with unresolved resource inherited Circuit Board
  from an unrelated chain on the other side of a smart splitter.
- `belt_item` iterative propagation skips CustomSplitter siblings.
- ChangeItem pass skips CustomSplitter (its three outputs are allowed to
  carry distinct items per smart-filter semantics).

### 12. Logistics item forward-propagation
- `src/sav_import.cpp`
- At-wire mirror (`out_pin->node->IsLogistics()` branch) no longer copies
  the downstream pin's item onto a logistics output. Was the cause of
  Coal storage chains being mislabeled as Circuit Board when the chain
  ended at a Circuit Board consumer.
- Forward-propagation pass now also moves items:
  - Logistics: output `item` = first non-null input `item`.
  - Link copy: downstream input `item` = upstream output `item`, but
    only when the downstream is itself logistics (org/sink/craft pins
    keep their own item).

### 13. Items not yet addressed (carryover)
- The Circuit Board contamination of the storage chain still reproduces
  after #11 + #12. See "Open issue" at top.
- `Build_PriorityMerger_C` is still treated as `unknown` by the wrapper
  (would need a prefix in `classifyBuilding`); discussed but not patched.
- Smart-splitter filter rules (`mSortRules`) and priority-merger
  priorities are not preserved on import. Planner is a steady-state rate
  solver; not modeled.
